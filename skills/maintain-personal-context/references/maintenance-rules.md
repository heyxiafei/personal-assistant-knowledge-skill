# 来源、确认、冲突与纠错

## 三个存放层

| 层 | 内容 | 准入 |
| --- | --- | --- |
| 稳定档案 | 自述背景、角色、经历技能、已有资源、明确目标摘要 | 用户确认；未知可以显式保留 |
| 日常日志 | 用户指定的事件、项目动作、临时感受、候选 | 保存本次材料已有授权；候选仍标待确认 |
| 精选长期结论 | 对今后帮助有价值的成果、反思、工作原则、持续目标 | 有依据与用户确认；推断/建议始终保留类型 |

七类是组织提示，不是填写任务。允许简短、缺项和未知。专业资料仍可在 Obsidian 等原处保存，这里只存与个人目标/项目相关的引用及理由，不搬全文。

## 每条内容的证据

保留明确可定位来源，如“虚构自述.txt，第2段”。来源访问不了则注明未验证；不要编造 URL 或文件位置。公开示例只使用虚构成人素材。
区分事件日期、记录日期、生效日期、确认日期；不详写未知。用户确认表示“同意保存此表述”，不是独立事实核验。事实更准确地说是来源明确陈述的事实。

不要从行为推断敏感身份、诊断、人格类型或固定价值观。即使用户主动提供私人内容也只在指定私人位置保留必要范围；不是公开包的示例素材。

## 确认与回答

明确写入或纠错的指令就是对具体条目的确认，引用该指令及日期，无需再问一次。无法判断确认范围时给具体候选，不改稳定档案和长期结论。
事实、推断、建议分别标注。助手建议不能变成用户已承诺的行动；资源名称不能变成其联系人已同意合作的证据。日期未知不能被自动补成今天。

回答优先选“已确认、未被替代”的条目。待确认/未知只能说明存在信息缺口；已被替代条目只供历史解释。推断被用户认可后仍是推断。

## 增量与人工编辑

先完整读取相关文件/页面。局部工具结果不能被用于整页替换。
同一个事实重复输入只合并来源，保留稳定 ID，不重复建页或条目。同一文本但不同事件日期可能是两个事件，不能盲目去重。
用户修改始终保留。冲突时展示旧文、新文和来源，仅对已有明确授权范围合并。支持工具使用计划时，在写入前核对文件哈希；有变化重新读、重新做计划，不绕过冲突。

本地助手的管理块之外可自由写备注；管理块内手改造成可读内容与 JSON 元数据不一致时，每次计划都会拒绝，重读/重计划不会自动修好。先保留完整私人副本，人工核对并恢复已知合法管理块，将需保留的改动放到块外备注或经确认的新输入后再计划；也可转为普通 Markdown 维护，不让工具覆盖。助手不宣称普通编辑器与它之间有绝对无竞态的多文件原子事务。

## 纠错与状态变迁

明确暂停、取消或关闭项目时，核对它的当前状态和全部推进型下一步。用同一有来源、已生效的决定替代已失效的旧动作并保留历史，不只追加状态却把旧待办留在当前投影。尚未决定的恢复或新动作继续待确认，不能据旧材料自动重开；其他项目的动作不受牵连。

新说法不一定推翻旧说法。“从某日起转岗”是状态变化；“先前技能描述不准确”才是纠错。
明确确认且变化已生效后：新条目引用旧 ID，旧条目标“已被替代”，保留替代前状态、原来源与确认依据。原来未知且无来源的历史仍是未知，不为它编来源。原说法换 ID 重放、内容及来源/日期/确认依据相同，也只识别为历史；真正新的确认或不同事件/生效日期不能按历史重放丢弃。
历史合并过多个来源时，重放其中已知来源的子集仍属于旧历史，不重新激活。稳定档案和长期条目仅改变整理日期不等于重新确认；日常日志仍按日期区分，真实不同事件日期、新生效日期或明确新确认应保留。工具只比较给定字段，不推断陌生来源是否代表同一历史。

本地工具的新 ID 历史重放决策如下；来源/确认/日期的前置校验始终先执行。历史身份匹配使用原状态、层、类别、类型、规范化正文、事件/生效日期、原替代关系及原确认；日常记录还比较记录日期，稳定档案/长期条目忽略仅重新整理的日期。

| 条件 | 来源 | 处理 |
| --- | --- | --- |
| 新 confirmed/pending 缺来源 | 空 | 格式校验拒绝，不放松证据要求 |
| 匹配原 unknown 历史，仍无确认 | 空 | 只识别历史重复，不变成当前事实 |
| 匹配历史身份与原确认 | 全部是历史已知来源，包括子集、顺序或重复引用 | 历史重复，不改写已合并证据或恢复当前状态 |
| 匹配历史身份与原确认 | 任一新增来源，包括仅新增或已知与新增混合 | 停止计划并要求核对；新增证据不等于新用户确认，不能继续追加旧事实 |
| 身份/真实事件或生效日期变化，或明确新确认 | 合法来源 | 回到正常流程，仍须通过来源、确认、日期与冲突校验 |

同 ID 输入仍走既有不可改写检查；合法来源补充可留在该历史记录内，不能重新激活。若用户确实要恢复旧说法，需要实际明确的新确认，不能只因多了一份来源就编造确认。
有生效日期时，先取得用户/调用方明确的比较日期 `as_of`，不从系统时钟、记录日期或时区推断。未到生效日的变化只能保存为明确标注的已确认未来计划，放入日常记录，不提前替代当前项；回答时将其说成计划，不作当前事实。到期不自动激活，需另一次明确更新授权与生效日期上下文。
冲突未解决则并列来源、标待确认。不能通过最新时间、语气强弱或第三方断言自动裁定。

## 数据主来源

在 INDEX 指定本地/Space 主来源；项目例外要单独说明。副本标来源、导出时间、相关源版本。副本已有修改则先比较差异，不能自动回写。
切换主来源需要对方向与范围作出明确决定。删除、共享、公开与扩大权限是额外动作，不能由“维护个人档案”推导授权。

## 跨页更新与确认日期

补充/更正前为每个主条目列出全部受影响投影：项目摘要、工作台、稳定索引、来源纠错。优先让投影引用主条目；保留摘要时也须更新或明确待同步。逐处重读与守卫写入，全部相关读回一致才算这次更新完成。跨页无原子事务，部分成功记录已应用/未应用及继续位置，不重放成功项、不用局部成功掩盖旧摘要。手改冲突先保留并处理。

日期依据逐字段判断：消息时间是记录日期；事件/生效日期须有内容或明确元数据依据；保存确认日期来自明确保存消息或本次实际授权，不从历史消息日期复制。缺确认来源则确认日期未知。一般成果自述不自带保存同意，也不自带精确事件日期。
