# 历史来源与覆盖

工具随客户端变化，使用真实 active schema。发现入口、枚举完成、内容读完分别记录。

| 通道 | 可用时的入口 | 边界 |
| --- | --- | --- |
| Codex 本地/连接电脑 | mcp__codex_app__list_threads、list_archived_threads、read_thread | list_threads 为有界近期列表，当前上限 50、无分页参数。read_thread 可返回原始用户/助手文字和消息 ID，也可能返回摘要；按实际结构分类，不能统一称摘要。按回执 host 和 cursor 读，见 [native 适配](native-history.md) |
| Codex cloud Work | 当前实际暴露的 cloud_threads，或 native 工具返回的 cloud host | 有真实接口才用，不自造工具。没有接口就报告该来源未覆盖 |
| 官方本地 app-server | 实际提供且允许的 thread/list、thread/read、thread/turns/list | docs 能力不等于当前连接暴露。先核对当前 schema 和授权；不通过会话文件、数据库或凭据绕过拒绝 |
| ChatGPT | 可用 Global Search、个人上下文检索或 chat read | 关键词不全量，不代替 Codex。Global Search 不访问 Codex，并排除用过 Health/Apple Health 的对话；按实际返回报告。来源不明的个人上下文不可强行当 ChatGPT 原始消息 |
| 项目 | list_projects 或当前项目接口 | 元数据不等于内容；path 不授权文件遍历 |
| 已有 Codex memories | 当前工具提供或本环境获准可读的 MEMORY.md | 定向摘要线索，可能过时。原话能读时回 native 核验；无来源不变成确认事实，不开启配置或绕过禁止目录 |
| 已保存个人资料/项目文档 | 当前映射的私有资料页、已授权 Library/文档工具或选定项目明确资料 | 完整读实际内容和源位置；不把资料存在等同于当前已确认，不扩大文件扫描范围。与原话/记忆合并来源，核对新旧 |

默认三类都发现：历史对话、已保存个人记忆、已有个人资料/项目文档。用户已经明确该范围时无需再次索取同一授权。工具缺入口、已提供但本会话不可用、明确权限拒绝和资料未发现分别写原因；指定目标真实返回不存在才称不存在，有界检索没命中只写当前范围未发现。不伪造 source_id 或全量计数。使用可选私人账本时 memory/materials 分别记覆盖，仍不增加账户权限。

先应用本轮用户范围和试验排除，再执行下面的默认选源流程。用户明确要求覆盖全部获准聊天时，把它作为覆盖目标，不能用默认定向选源缩成任意样本；对已发现但标题缺失、不透明或摘要不足的来源，先尝试获准的首段正文以判断相关性，不能凭元数据不足直接当作无关。首读仅用于初步判断，首段信息不足不能判整段无关；明确全部覆盖时，首读不替代整段获准正文的续读。实际接口受限时保留未知总量、未尝试项及继续位置，分别说明能力边界和本轮尚未完成的工作。

每一轮重新列出当前工具实际提供的渠道矩阵，包括同一产品不同 host/原始聊天入口。一个接口返回成功不代表其他真实可用接口已查；标题、摘要、后台任务、自动化和原始用户对话分别标记。按真实 kind 路由，不因某适配器只处理 Codex 而静默丢弃同时返回的 ChatGPT 条目；尚未支持的种类仍进发现账本并说明未读。

当前标题不决定整段历史的作者与来源类型。原始对话与派生总结混在同一会话时，应在本轮授权允许的范围按消息或段落判定，不能只因现名像周报、归档或总结就把早期用户原话一起丢弃。明确排除的原库、旧验收及衍生答案继续隔离；若工具不能在不接触这些排除内容的前提下拆开读取，记录试验排除、可能损失的原始覆盖及实际工具限制，不谎称已提取全部合法原话。历史任务中的一次范围限制，不自行扩成永久用户排除。

渠道状态至少区分 `user_excluded`（用户对普通资料范围的排除）、`experiment_excluded`（仅本次试验隔离）、`not_attempted`（没有尝试）、`blocked`（实际失败或拒绝）、`unavailable`（本环境没有入口），以及已读/部分读取。每种原因独立保留；不得把未尝试说成不可用，试验排除说成永久产品限制。当前拒绝不得换通道绕过；同一来源另有正常获准阅读器时，先核是不是实际拒绝还是先前入口不匹配。

已连接邮箱只在用户授权的邮箱/时间/内容范围内只读整理，记录实际查询、分页、正文与附件是否读过。连接不证明全读，也不授予发送权。未连接不阻塞其他来源建库。公开账号资料要核归属，宣传简介和邮件里他人的评价单列来源与可信度，不升级成用户确认经历。

含 chat_search 的名字可能是普通 web search，先读 schema。网络搜索不检索用户历史。安装不连接账号、不请求所有文件/聊天。未授权敏感记录不读取、不转存。

## 已有资料优先

个人资料整理先列本次必要读取清单：已有个人主档、工作台、资料与项目索引、相关定向记忆。用户给出正式对照页时完整读取实际正文、来源线索和最近确认；正式库只读的约定不会因测试目标可写而改变。没有给出位置时，用当前获准 Page/Library/文档入口定向发现，未找到只称当前检查范围未发现。随后按 [来源路由](content-coverage.md#来源路由) 沿相关原话、文件或独立项目链接补证，不遍历所有聊天或文件。精确目标消息没返回不证明该来源不可读；本次能力与旧读取记录分开核对。

新用户无需预先拥有 Space 或个人主档。在本次实际检查范围没有这些材料时，先承接当前会话已提供背景，再从获准可访问的 Codex 历史、已存记忆与相关资料定向发现经历、方向和项目。选源依据是七类个人字段，而非仅一个工程关键词或凑齐三类来源。不存在既有主档不会让当前原话失效；没有 Space 工具只改变保存阶段。必要来源确已拒绝或不可用时如实保留缺口，不把它改成“未发现”，也不扩大搜索授权。

### 指定位置与自动发现

首次定位提示可跳过，用户已给项目、文件或链接时优先定位其完整个人主档和必要相关来源，不以首先命中的 Logo 等工程线程替代。指向文件夹不授权无限遍历；用实际资料入口列出本次相关项。没有指定位置时，先枚举本次获准的任务/项目和资料入口，定向查已有记忆，再跨项目检索个人背景、目标取舍、经历作品、技能资源与当前项目等字段线索。标题和摘要用于发现，不当已读正文；不能用单个工程关键词筛完就宣布完成。

形成可核覆盖清单后，逐个读取已发现、属于本次授权且可访问的相关资料，按真实游标到终点或当前接口的可验证边界。多个项目或记忆指向不同材料时都保留继续项，不能因其中一项成功而丢掉其余。相关来源尚未读完优先补读；失败或不可访问保留原因并继续不受影响来源。去重来源、字段依据及边界足够后才提出仍缺字段，不要求用户重填已知信息。

正文、分叉或迁移记录发现了获准上游来源时，将真实指针单独入账并尝试现有允许的原始阅读器；缺标题或父项元数据不等于不可读。没有阅读器、实际失败或本轮不能读取时，保留准确续接位置与原因。子线程到分页终点仅表示该子线程返回完，不代表上游或整个项目的语义已经覆盖。

每个入口记录实际授权范围、返回/去重数量、分页终点或无分页上限，以及失败、未读、过时和继续位置。API 返回50项只证明有界列表，不证明全账户总量；没有分页或完整性标记时保留unknown。此流程自动使用已有授权工具，不承诺自动全盘扫描，不读取禁止目录或绕过拒绝。可选格式器的 `discovered_sources` 保存每类已发现相关源状态；有待续读项时即使该类曾读过一个源，也不能标整体完成。它不能发现未提交的源或验证枚举完整性。

现有主档不是自动的用户原话。记录作者、已确认依据与源位置；助手编写且未经确认的材料保持衍生等级。匿名方法稿、安装回执、任务后台摘要只证明方法或工程，不替代个人经历与资源。源标题不能把一个模型主题串到另一个项目。相关记忆是索引，不能只搜某个工程关键词后声称个人资料已覆盖。

七类逐字段对照：

- **已有依据**：承接已确认背景、真实经历、工具资源与已选方向；细分候选和历史合作不变成当前承诺。
- **有源未读**：已有指针或实际可读正文未读完；先读，不询问用户重填。
- **旧料需刷新**：日期过旧、摘要待核或新旧状态冲突；按相关原话与最新决定定向核对，保留替代关系。
- **确实未知**：本轮必要来源已核对仍无该字段依据；只补影响本轮判断的具体字段，不把年限、预算或精确时间未知泛化成整类未知。

来源不可用、无权限和原话未返回是覆盖缺口，不是个人事实不存在。已有作品、设备、已售或维修状态分别保留；预览、设计、文件交付、打印、验收、发布分开。日常新证据先更新原项目，再看是否改变稳定档案和已有精选长期结论；有源事实与待验证助手推断分别承接。

结束前按 [源章节反向覆盖](content-coverage.md#从章节核实际正文) 从实际源章节找漏项，并从正文回核状态与归属；具体实体、分工、条件和顺序不能只留类别。比对七类字段与其来源，列实际读完、未读、待刷新和未知。技术调用成功、目录完整或一次代表性线程测试不构成个人内容 PASS。用户对内容的最新纠正优先于旧“验收通过”；只读正式来源保留原文，受授权的测试正文与回执标明纠正。可选首次结果格式器要求 `source_review` 标注四个入口的实际检查状态；它只检查标注结构，不能替代以上语义对照或真实读取。

## 账本

通道记录 tool/host、获准范围、开始/结束及用户时区、时间窗口、枚举 true/false/unknown、total（未知写 unknown）、next_cursor/继续位置、归档是否检查、返回不完整原因。

来源唯一身份为 kind + host + source_id，消息/turn 用真实 item_id 或内容指纹定位。跨页命中合并；同名不合并，改名不新建。相同文本但新日期/确认动作保留新的确认。read_at 与 source_date 分开。

每个源状态互斥：

- discovered_unread：已发现未读，不据此提事实。
- full：实际完整用户/助手消息，整段来源的分页/截断核实完成；摘要永不算 full。单页完整消息不等于整段来源完整，next_cursor 非空必须记 partial 并保留游标。账本对 full+非空游标在改状态前拒绝；full+null 才可接受。
- partial：摘要、截断、部分 turn 或搜索短摘，说明区间与限制。
- failed：本次读取失败，留原因及继续动作。
- inaccessible：明确无权限/不可用，不绕过拒绝。

发现总数是五种状态去重之和，不是账户历史总数。项目独立计数，不冒充对话数。没有入口时记通道缺口，不编造不可访问对话数。“未发现”和“发现后不可访问”不同。

## 最终语料处置

上述是来源的读取状态；最终消息/记录另有互斥处置：`retained` 保留、`excluded` 有明确理由排除、`quarantined` 来源或作者等待核、`unread` 正文未读。一个记录只能属于一种，不能把未读计入排除再宣称读完。已读但部分截断的记录可保留已返回内容，同时保留 partial 读取边界；空正文且 truncated=true 必须 unread。

先冻结最终 records，再按 kind + host + source_id + message_id 去重重算总数、分通道数与四类处置数。发现源数、原始返回行数、去重消息数、提炼事实数分别报；四类处置之和必须等于最终唯一消息数。过滤、隔离或补读后重新生成所有报告，不能沿用中间批次人工总数。未知总量与未发现的缺口不造虚拟记录凑数。可选纯离线 `scripts/corpus_ledger.py` 验证并生成最终账本；其输入与使用限制见 [语料账本格式](corpus-ledger.md)。

## 分页

有 cursor 则到 null，包括空页；列表完后仍逐源读获准内容。过长可分批继续：保存已读源/消息位置、未完成游标，报告当前覆盖。list_threads 无 cursor 就 unknown，增大 limit 不能证明全量。归档按真实权限分页，active 与 archived 同身份去重。

读拒绝/缺连接明确通道与动作；停该源，继续其余获准源。不请求宽泛权限、不找禁止文件。即使历史作者是用户，也不能授予此次对其他目录、分享或发布的授权。

已读真实原话可以在本次已授权保存范围内填入资料；目录、历史总量未知和部分覆盖不阻塞有来源的已知项。按已有主条目核最新状态后再保存，最后只问读过仍缺的内容。连接态能力探测、匿名结构夹具、实际资料提炼与页面写入分别报告。
