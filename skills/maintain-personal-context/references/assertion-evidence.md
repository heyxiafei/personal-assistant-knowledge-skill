# 事件状态与来源证据

适用于把原始材料整理成事实、尤其是用新内容替代未知状态时。先读原文及作者角色，再标注；不能先写“已完成”，再补一份确认保存的指令当证据。`status=confirmed` 指保存确认，`assertion.state` 指来源所述事件状态，两者独立。

- `observed`：用户明确陈述已发生或当前状态。保留否定、对象及完成阶段；“技术检查通过”不扩写为用户验收，“已上传”不扩写为发布成功。真实完成、明确取消或对错误完成状态的纠正均可记录。
- `planned`：意图、预计、条件成立后的行动。即使预计时间已过，也只能留在日志，不替代当前未知事实，不激活任务。
- `uncertain`：问题、推测、第三方建议或不能确认的转述。保留原说法和作者，不当作用户已完成事实；有明确纠正再更新。

本地 helper 的新增 `assertion` 字段包含 `state`、`author_role`（user / third_party / assistant / unknown）、`source`（与 sources 中某项一致）、`source_text`（本条来源完整上下文，最多 6000 字）和 `statement`（其中一个完整原文分句）。`text` 必须逐字保留这个分句，可省略末尾句号。分句以引号外的中英文逗号、句号、分号或换行划分；小数点、版本和文件名内部的点不拆句。不能截去条件、否定或引述前缀。一个分句含义不独立时，保留未知并请求更明确的用户陈述，不能为通过脚本删除上下文。

```json
"assertion": {
  "state": "observed",
  "author_role": "user",
  "source": {"label": "本轮虚构用户自述", "locator": "message-1"},
  "source_text": "我已经完成制作。",
  "statement": "我已经完成制作"
}
```

新条目替代 unknown 事实时必须提供 observed 证据；缺失或不满足检查会拒绝计划，原文件不变。planned / uncertain 证据只允许 daily 且 supersedes 为空。只改枚举不能洗成完成：observed 还检查用户作者、完整原文分句及来源绑定，拒绝常见未来、条件、建议、疑问及转述。脚本故意保守，混合或复杂原文可能被拒绝，应保留未知并确认，不能换词绕过。普通当前事实也拒绝含明显未来或不确定表达的 profile / longterm 写入。

observed 检查所选分句及本句在它之前的条件、引述或时间限定；后面的独立计划不会否定已经明确陈述的真实完成或撤回。须保留完整 source_text，不能删除上下文来通过检查。同一原文中所选分句重复出现或指代关系不清时，保留未知并确认。

事实可以是状态、数量、名称或已发生事件，不需要命中“完成／通过”等动词白名单。由读过原文的助手判断 observed 是否成立；脚本核对证据绑定并拦截明显矛盾，不会仅因未匹配某个动词就把合法纠正留成旧事实。未识别到拒绝词也不证明来源肯定，语义判断和读回仍须执行。

作者字段写 user 不能把引述变成用户亲历证据。整条分句只是引语，或前置“说／表示”等报告谓词仍在作用域内时，不能 observed 替代。句内题名、编号等引用可完整保留；判断其外部用户陈述，不能把引文内部的“已完成”当成外部证据。引号不配对时保留原文并确认，不删引号绕过。独立未来意向后明确以“现在／目前”等开始的当前分句可以单独保存；此时间重置不能逃离前置条件、不确定或报告人的作用域。“还没”等明确否定可保存为当前未发生状态，不能推成完成。

直接引语以句末标点及配对引号闭合后，后面的用户独立陈述按自己的作者和事件状态判断，例如“我尚未核实”“也没有申请”不能仅因前面有他人原话而丢失。该边界只结束引述人的作用域，不消除外层条件、预计、不确定或后续新的报告谓词；未闭合或语义仍依赖转述时保持待确认。完整 source_text 仍保留引语与后文，不截断证据。

当前否定或持续状态可与前面的独立意图分开，不能把“打算报名，还没有报名”中的后句也当成未来。外层条件、近邻不确定限定、纯未来时间限定和报告人仍保留作用域；出现独立当前分句后，不把更早的可能变化无限传递下去。“某某计划还在评估”中的项目名称不是“我计划做某事”的动作意图。这里仍是有限语法守卫，复杂语义需读原文判断，不能把没有命中拒绝词当作事实认证。

旧复合输入不能整段当作一个当前事实。例如明确取消后又要求“以后不要重开”，应以逐字取消分句记录当前状态，完整原话保留在 source_text；后续约束仍须遵守。不要为兼容旧输入放宽守卫、删去原始约束或重新激活任务。

同一事实和事件换了来源消息，不是第二次发生。结构化条目以事实正文、事件/生效日期、状态、作者类别和替代关系核对身份；新来源只合并到稳定条目。计划、未知、观察状态及真实不同事件仍分开；已替代历史的新来源要先核对，不能据此重新激活。旧式无 assertion 条目不自动转换，跨格式重复须先读既有内容并保留稳定ID。

旧条目继续可读，历史重放保持幂等；不会扫描或自动改写旧错误。旧库中已错误替代的事实需阅读原证据后用新确认条目纠正。新字段不代表已读取外部来源：helper 只检查调用方提交的原文，不认证作者身份、来源真伪，也不保证覆盖全部语言表达。来源读取、语义核对和独立审阅仍是必要步骤。未走此 helper 的 Pages / Drive 更新也要先做同样的判断，但没有本地脚本的自动拦截保障。
