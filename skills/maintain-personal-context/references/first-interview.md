# 首次访谈：覆盖、补缺、预览与保存

首次显式调用先按 [连续上手](onboarding.md) 在获准私人目标建立空白骨架，保护既有库和手改；再读取获准资料填充同一库、给初步建议和选填表，填写或跳过后更新并深入建议。无资料也可建立获准骨架；授权不足才暂停相关保存或读取。本页是建库后的可选补缺与旧会话兼容，不撤销已有建库授权。

## 先展示实际覆盖

可展示一次可跳过的定位提示：“有已经整理的项目、文件或页面可以直接告诉我；没有也可以从本次获准来源开始。”已给位置不重复问。调用不授予新账号权限；范围不明确时只发现允许的入口与数量，明确拟读范围后补问，不能因工具存在就全读。

按 [历史覆盖](history-coverage.md) 读取已有主档、工作台、资料与项目索引和相关记忆，再沿必要原话补证。先给简短清单：

| 项目 | 展示内容 |
| --- | --- |
| 本次授权 | 实际账号/来源类型、选定项目或资料、允许的时间窗口及排除项 |
| 实际读到 | 可定位来源、原文或摘要、已读时间/页/消息范围、分页或截断边界；日期未知写未知 |
| 尚未覆盖 | 未读、待刷新、未发现、工具不可用、拒绝及排除分别说明，列可继续位置；账户总量未知不凑数 |

这是读取回执概括，不把标题、搜索命中或一次接口成功写成全量阅读。可读必要来源未读完先续读；确定受阻则停止该源，继续其他获准部分。覆盖清单之后立即展示四段可纠正初稿，再判断哪一题仍需要访谈；不等待用户答齐资料。

## 四段初稿与纠正

先按 [首次结果](first-run-result.md) 展示“你是谁／你在做什么／你接下来做什么／建议”，带当前版本标识，区分已保存骨架与尚未获准保存的新增内容，允许未知或暂无建议；然后再逐题补缺，随答更新四段。每段区分可靠事实、初步理解与待补，来源可回查；初步理解不因用户回答其他题而变成事实。下一步和建议合计最多三条，均写依据；建议带第一步和采用条件。没有依据可以暂不提建议，不将暂停、取消或关闭项目恢复为推进动作。

用户纠正时先更新有关事实、项目状态、下一步和建议，再展示受影响内容及新版本；不能只改简介而保留依赖旧事实的方案。保留原来源与纠错关系，未知日期不补为今天。用户标“这项不保存”的内容不进入保存计划或新断点；若需本轮讨论也按其明确允许的范围使用，不引用敏感原话反复展示。

确认“当前目标是什么”不表示目标已经实现。含计划、准备或未来条件的目标保留计划属性；使用本地保存器时放日常计划，并从画像引用，不能为塞进稳定事实而删除这些限定。已知现状或近期目标足以说明主线时，不因缺少某个内部字段名再问同一问题。

## 默认快速入门与旧四题兼容

建库后的可选补缺见 [短题流程](quick-start.md)：展示来源与预填摘要，首轮最多八题、每轮一题；全部已知可零题，已答、跳过和不保存的进度保持。6–8 题、3–5 分钟为未验证的设计目标。用户可随时暂停或结束首轮，立即用当前初稿协作；更深入的经历、取舍和复盘只在后续有用且用户愿意时询问。

下面四主题是 revision012 `interview.py` 的兼容流程及旧离线会话包上限，不再作为新快速入门的完整题单。保留它以读取旧进度，不把未覆盖更多主题视为旧答案失效。

在初稿展示后，按下列四个主题选择仍缺或矛盾且影响本轮初稿的内容；已经有明确依据就跳过，不要求用户重述。矛盾只引用有关说法与来源，问当前哪一项适用，不重填整份档案。四题不是必答表，仍有待核项可保留到初稿。

| 主题 | 可问的一个焦点 | 选项例子，须按已知内容调整 |
| --- | --- | --- |
| 现状 | 你当前主要在做哪件事？ | 已有项目候选、当前没有固定项目；不凭选项编造用户身份 |
| 近期目标 | 最近最想推动或解决什么？ | 已有目标候选、先整理现状；不把目标说成已完成 |
| 约束 | 现在最影响推进的约束是什么？ | 时间、资源、明确不能做的事；不索取敏感明细 |
| 协作偏好 | 这次希望助手怎样配合？ | 先给简短方案、先比较选项、先听补充；本次选择不自动成为永久偏好 |

两种流程每题都说明为什么还需核对，接受其他和自由补充，并允许“跳过”“暂不确定”“这项不保存”“暂停”“先用当前初稿”。跳过或不确定保留缺口，不用默认选项代答。用户已自行补充多个主题就承接，不再逐题照问。答题本身不扩大既有保存授权；已有授权覆盖的更正按范围更新同一库，额外断点需另获授权。

当前环境确有原生选项工具时，先读其实际 schema，用它展示本轮一题与适合的候选。自由回答以及跳过等选择须有真实可用入口；工具不支持时明确接受后续文字回复，不伪造控件、按钮或成功回执。无工具时以 A/B/C 等标记相同候选，保留其他、自由输入及所有控制动作。安装不强制弹窗或自动挂载页面。

用户可使用客户端或系统已有的语音转文字，再发送文字答案；按收到的文字处理，允许先纠正识别错误再进入初稿。Skill 不新增录音、转写服务或后台监听，也不把收到文字称为听过原音。内容含混时只核对有关片段。

## 确认当前版本与具体目标

保存前说明当前初稿版本、将保存的条目与目标（既有私人 Space/明确本地目录），区分用户事实、待核内容及建议区。用户可确认、指出具体纠正或选择稍后/不保存。确认只绑定所展示内容、授权范围和目标，不包含扩权、外发、恢复项目或执行建议。

已有本次明确保存指令且足以覆盖当前版本与目标时，沿用该授权并说明依据，不再询问同一动作。来源范围扩大、实质内容版本改变或换目标时，核对新增差异是否已有明确授权；用户仅回答访谈问题不是授权。用户纠正并明确要求保存该更正时，可按其具体指令执行。

已有授权覆盖时读 [首次建库](space-onboarding.md) 或 [本地工具](local-helper.md)，在已建立的主来源增量更新，保留手工修改、稳定 ID、来源和替代历史；全部受影响条目与投影读回一致后才报告完成。仅预览时不给虚构入口；Space 缺工具、权限或私有证明时明确未保存到该目标。

## 断点、恢复与不保存

默认只在当前对话保留进度，不另写文件。只有用户允许保存访谈断点时，才在公开仓库和已安装 Skill 之外的指定私人位置保存最小进度、当前初稿/版本、来源边界、已答/跳过/不保存项的状态与待续题；“不保存”内容只留排除状态，不写其答案。不得把完整私人历史复制成断点。

单项“这项不保存”排除该项，不妨碍其他另获授权的内容；整轮选择不保存时，不新建或更新断点、导出或该轮内容；已按此前授权创建的骨架如实保留。若已经存在此前获准保存的断点，如实说明其存在与本轮没有更新；不承诺它已消失，也不暗中删除、覆盖或清理。删除已有文件需明确处理授权。此约定只控制 Skill 的额外持久化，不代替客户端自身的对话记录管理。

恢复已获准断点时，先读其版本、来源范围与目标，并核对当前实际主条目；保留旧答案、来源、跳过和不保存状态，不重复已答题，不自动激活旧确认。快速入门迁移在内存中进行，只有另获断点保存授权才写回；不重建空白会话或覆盖旧文件。新增纠正先形成新初稿，确认是否覆盖后再交给保存器。没有获准文件就基于当前会话可见内容继续，缺失上下文如实说明。

## 可选本地 helper

新快速入门使用 `scripts/quick_start.py`；先读 [使用与边界](quick-start.md)。它复用 `scripts/interview.py` 与 `first_run.py` 的来源、纠正、保存和断点守卫，旧四题 helper 仍可按其实际 docstring 使用。这些脚本只处理 Agent 已判读的标注，不读取历史、不调用选项 UI，不是自然语言提取、事实核验或授权识别器。也可直接在当前对话执行流程；未获文件保存授权时，不为运行脚本先创建私人输入或状态文件。

准备保存时，用 `draft(session, target=具体目标, reviewed_plan=已审计划)` 展示目标与实际拟写正文，并取得本次 token；再由 `confirm` 核对这一绑定。普通初稿 token 不能授权另一份未展示的计划。纠正、改目标或改计划后，旧 token 失效；纠正会清除旧建议，须重新核对建议再生成可确认的预览。token 检查只是结构守卫，Agent仍须核对真实用户授权，不能自行制造确认来源。

`apply_local` 只向明确且已经初始化的本地目标交给现有 `context_store.py` 事务写入；真实 Pages 仍使用实际工具及 `space_state.py` 流程。可选断点需单独获准，恢复时取得的字节 hash 用于后续守卫写入；手工修改或版本冲突先核对，不绕过锁或覆盖。选择不保存不会暗中清理旧断点。

`first_run.py` 继续提供来源与四段格式辅助，旧格式的信息动作不替代本页每轮一题规则。实际入库、手改保护与恢复按保存器及回执判定，不能以预览、问答或 token 冒充已保存。

需要把已读标注和未答阶段保存为可移交快照，或提供实际可用的离线选项页面时，按 [私人会话包](session-reuse.md) 另行创建；保留本页的文件保存授权与正式库保存边界。
