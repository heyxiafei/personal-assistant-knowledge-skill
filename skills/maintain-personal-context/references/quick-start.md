# 快速入门：先承接资料，再补最小缺口

首次显式调用默认使用本流程。目标是尽快让助手能够基于实际背景提供帮助，再在日常使用中深入补齐资料。首轮 6–8 题、3–5 分钟只是拟议设计目标，尚未验证；实现上最多八个短题，已知可以零题，任何时刻都可结束首轮。不要把固定题数、资料完整度或长访谈完成当作使用门槛，也不输出人格类型或诊断。

## 读取与预填

先按 [历史覆盖](history-coverage.md) 使用本次已经授权且当前可读的入口，优先承接已有个人主档、项目资料、相关记忆与必要原话。用户已给范围、位置或排除项时直接遵守，不重复询问同一授权。读取范围不清楚时先说明缺少的边界；安装本身不授权整个账户读取，不为此扩权或读取禁止目录。

先展示实际读取清单：来源、时间或分页范围、是否原文、摘要与附件边界、未覆盖项及原因。有明确可续读的必要资料先续读，不能为了凑题数要求用户重填；权限拒绝、工具不可用与未尝试分别记录。受阻来源保留覆盖缺口，继续承接不受影响的资料，不把受阻当成个人资料不存在。

从已读、经 Agent 判读的标注形成预填摘要，并保留每个值的可定位来源：

| 层级 | 含义与展示 |
| --- | --- |
| 已有用户资料 | 用户原话或自存资料已有依据；保留原日期和状态，不能冒称本轮重新确认 |
| 本轮用户确认 | 真实本轮回答或明确纠正；说明确认了哪一项，不同时确认其他候选或保存动作 |
| 摘要或推测待核 | 已存记忆摘要、助手推测、第三方说法或作者未核实资料；只作待核候选，不升级为用户事实 |

未知保持空白，矛盾保留相关候选和来源，不默认勾选。整体核对摘要不自动把所有推测变成确认。随后立即给 [四段可纠正初稿](first-run-result.md)，允许未知或暂无建议；首轮未答完时也能据此协作。

## 选择真正需要的短题

最多从以下八个主题各选一个影响当前使用的焦点，优先核对矛盾，其次补关键缺口。已有足够依据、旧答案已承接或本轮已处理的主题不重复询问。已审的 `current_problem` 若已说明本轮主线，近期目标直接复用这条依据，不为缺少 `near_term_goal` 字段再问同一件事。用户一次补充多个主题时同时承接，不照题单追问。

| 主题 | 本轮用途 |
| --- | --- |
| 现状 | 理解正在做的事或当前问题，不从旧任务推定仍在进行 |
| 近期目标 | 选准优先方向，保留计划与完成的区别 |
| 协作 | 了解这次希望助手怎样配合，不推定永久偏好 |
| 约束 | 把建议缩到实际时间与资源内，无须敏感明细 |
| 简介 | 只补理解当前背景所需的普通信息，不强制真实姓名 |
| 能力 | 承接已有经历、技能或作品，不由选项生成履历 |
| 资源 | 承接已有工具和可用条件，不索取凭据或通讯录 |
| 协作边界 | 明确本轮需要避免的做法；选择不扩大任何访问或执行权限 |

每次只提出一个问题，说明为什么需要它。已有来源候选优先显示；不存在候选时，可为本轮协作提供普通选项，也允许一句自由回答。选项不是默认答案，摘要不是确认，跳过和不确定不添加事实。

当前宿主有可用原生选项工具时，先读真实 schema，再提交符合其限制的候选；仅在实际结果支持时称已展示或已收到选择。工具不支持足够选项、自由输入或控制动作时，用后续文字承接这些入口。没有原生工具时，提供同样候选的 A/B/C 文本流程，例如：

```text
已有资料没有说明本轮协作方式。你希望这次先怎样开始？
A. 先给简短方案
B. 先比较几个选项
C. 先听我补充
也可回复：其他＋一句话、自由补充、跳过、暂不确定、这项不保存、暂停、先用当前初稿。
```

“其他”只有伴随实际补充才成为答案，不把“其他”本身写成人物事实。支持系统或客户端已有的语音转文字并允许纠错，不假装录音或读取原音。不要承诺安装即弹窗、自动挂载或任何宿主未提供的界面。

## 随答可用与后续深访

收到真实回答后更新预填和初稿；纠正同时使依赖旧信息的建议失效，重新核对后再展示。冲突只按实际明确纠正、来源与时间关系处理，不能为了结束题目悄悄丢掉旧说法。无法确定的部分继续列待核。

跳过和不确定保留处理状态，不添加事实。普通“暂不填写”“细节稍后补充”等选项只确认本轮安排，具体能力、资源等仍留可选细节缺口，不因选中泛泛选项便声称资料已完整。

“这项不保存”从当前状态剔除该主题规范 key 的正文、旧候选和依赖建议，旧排除状态在迁移时同样生效；共享同一说法的其他投影也不能保留其逐字副本。回执或覆盖说明中的逐字副本会一并清理，语义改写、归属和实际授权范围仍须 Agent 审核，这不是通用隐私审计。新断点、导出及保存计划不能再带入被排除正文；已经存在的旧文件本身不因此删除或改写。

暂停停止发题，在当前可见对话中保留进度；恢复只继续未处理缺口，不恢复旧保存确认。结束首轮即使用当前初稿，不自动进入另一份长访谈。

后续缺口清单说明哪些内容尚未知、哪些有冲突，以及补齐后能改善什么；用户选择某一项后再深入。已跳过、不保存或主动结束的部分保持边界，不因后续调用自动重新询问。建议仍是条件建议，不变成用户承诺、项目重启或执行授权。

## 复用旧进度与本地 helper

`scripts/quick_start.py` 复用 `interview.py`、`first_run.py` 的既有来源与保存守卫；它只接受 Agent 已经判读的标注，不扫描账户、提取自然语言、调用 UI 或写正式库。使用前读脚本 docstring，不推测参数。

在完整源码根目录运行合成输入示例，结果只输出到标准输出：

```sh
python3 -B skills/maintain-personal-context/scripts/quick_start.py \
  --input tests/fixtures/quick-start.json --case new
```

新预览使用 `start`，旧 `first_interview` 状态先经 `migrate` 承接原答案、来源、已答/跳过/不保存状态和幂等记录；不要重新开始空白会话。重复迁移不制造新答案。已经保存的会话不可变，迁移器会拒绝重开；后续维护从新的明确请求开始，并读取既有主条目作为资料。

`draft` 给预填、初稿与当前问题；`respond` 接收真实选择或自由答案，重复提交沿用原幂等守卫。`supplement` 承接 Agent 已核对的真实多主题回复；相同来源、相同规范内容重复传入不增加版本，来源身份相同但内容不同则需核对。已排除 key 不得通过补充自动重进，重新接纳需要用户新的明确请求。`pause`、`resume`、`finish` 控制本轮发题，`followups` 提供后续缺口供用户选择。它们都不构成保存授权。

快启状态只保留规范断言、来源回执及当前初稿与进度所需字段；入口、建议及 `project_context` 也只投影支持的字段，`raw_materials` 等未使用长文和回执中的原始消息正文不进入最小断点。运行中的快启状态若又带入未支持的原始字段，会拒绝使用或保存，保留原件供核对，不悄悄丢弃或复制到新断点。原始资料仍在原来源或原有文件中，不由快启迁移器删除。标注里仍应只放实际必要、获准保留的内容，不能把规范字段当作存放完整历史的容器。

默认在当前对话保留状态，不另写文件。只有另获断点保存授权时，才在公开源码与已安装 Skill 之外使用 `checkpoint`；`load_checkpoint` 读取后核对现有主条目、旧来源与目标，并使旧确认失效。写回继续使用上次读取的文件 hash 保护手改。完整保存和不保存规则见 [首次访谈](first-interview.md)。

已有 [私人会话包](session-reuse.md) 继续使用原 schema、摘要校验及最多四题的离线格式。迁移先校验包与绑定同一版本的回答文件，再由 Agent 核对每题的实际含义、主题映射和真实回复定位；代码不自动判断语义，也不猜来源身份：

1. 用 `session_bundle.read_bundle` 校验包，再用 `session_bundle.validate_responses` 核对回答版本、题目与选项。
2. `answer` 由 Agent 核对后写成规范 claims，通过 `supplement` 承接；`unanswered` 仍未答，不生成 claim 或处理决定。
3. `skip`、`uncertain`、`do_not_save` 通过 `import_decisions(session, decisions)` 承接，不能只转成 claims 而丢失控制状态。每行必须且只能有 `topic_id/action/submission_id/source_id`：分别为经审核的快启主题、这三种控制动作之一、稳定提交身份、实际已读回复定位。它不要求按当前待答题顺序导入；不保存会清除该主题正文，重复同 ID 同内容不改变状态，不同内容或与已有不同决定冲突时拒绝替换，先核对。

下面仅示范合成案例中“跳过”的字段与调用；`bundle`、`downloaded` 为 [会话包示例](session-reuse.md) 对应的合成包和合成回答对象，`session` 为快启预览。这里的 `fictional-*` 是合成输入定位，不能用于声称读过真实资料：

```python
normalized = session_bundle.validate_responses(bundle, downloaded)
reply = next(r for r in normalized["responses"] if r["question_id"] == "fictional-goal")
# Agent 已在本合成案例中核对：该题对应 goal，回答文件明确记录 skip。
if reply["action"] == "skip":
    session = quick_start.import_decisions(session, [{
        "topic_id": "goal", "action": "skip",
        "submission_id": "fictional-import-goal-skip",
        "source_id": "fictional-responses#fictional-goal",
    }])
```

真实迁移必须使用实际已校验的包、回答和来源定位；结构校验不证明语义映射正确。旧回答和控制状态不因更换入口而重问；导出、下载、结构校验及迁移都不等于正式入库，不携带新保存授权，也不绕过原包校验。

合成测试能验证预算、去重、来源分层、控制状态和私态隔离；真实资料扫描质量、宿主原生选项的实际显示与操作、零资料用户是否顺利、跨会话真人续答和作答时长仍需真实用户体验验收。
