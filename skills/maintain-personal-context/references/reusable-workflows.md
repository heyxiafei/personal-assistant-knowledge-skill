# 从个人资料到可复用工作

本流程建立在已读、有来源的个人库上。先交付库的实际入口、已有内容及查看/补充/纠错/更新方法，再做本流程。用户没有采用任何候选也可以继续使用资料库。

## 识别与选择

从实际重复的请求、输入和交付物判断哪些步骤可复用；保留支持该判断的源位置。一次临时要求只能是本次约束，不写成永久偏好。两次相似任务也不自动证明完全同一流程；核对目标、输入变化、共同步骤和成功标准。可复用性是推断，用户决定是否创建。

候选说明：它帮你重复完成什么、下次提供什么、得到什么、何时不适用、建议在哪个项目使用。不要一次给长列表；与每日行动/必要补问一起优先最多三项。预先检查当前可用的创建、文件、安装和 Work 工具，不能承诺不存在的能力。

询问用户是否创建这个具体 Skill，并确定作用域/安装位置。已有本次明确授权不重问；只有识别候选或同意研究，不等于同意创建。拒绝或取消记入当前候选状态，不写 Skill、不重问、不删除个人库。需要新 Work/项目时确认用户希望创建的对象与目的；遵守当前工具对新任务的授权条件。

## 实际创建与验证

1. 使用当前可用的 skill-creator；不存在时按目标客户端的已核 Skill 格式创建，不猜 API。普通模型任务可用清晰指令，确定性重复转换才加脚本；不要为每个候选额外搭框架。借用第三方组件前核官方能力、版本、许可证和依赖，不把候选研究说成已集成。
2. 保存前核目标是否已存在。相同请求重复到达：读取现有 Skill、版本和创建回执，返回它的实际入口；不生成带编号的重复副本。同名但归属未知不认领；已有手改不覆盖。升级需比较版本并保留原文件。
3. 使用适合目标作用域的真实发现位置安装。普通目录中的 SKILL.md 只算文件创建；“已安装”需要位置/文件/版本核对，“已发现”需要目标客户端或新会话能实际加载。若工具只允许当前目录写入，不能把临时文件说成用户级安装。明确告诉用户下一轮或新 Work 应怎样调用。
4. 检查 frontmatter、引用、脚本和权限边界，运行一次代表性输入。展示实际输入、调用入口和输出位置；检查交付是否满足约定标准。脚本退出 0 不能证明内容正确，人工语义核对另记。
5. 在新的 Work/独立新会话，使用另一份真实或虚构且获准的输入，从已安装位置发现并调用。新执行者只拿用户请求、安装位置/实际可见 Skill 与必要输入，不拿前一答案。记录 Work ID、是否自动发现或显式按路径加载、输入/输出和版本。只在同一模型里改输入重跑不能写“新 Work 复用通过”。
6. 若用户取消发生在创建之前，停止写入。若已创建，停止尚未执行动作并报告已有对象；不要自动删除用户文件。若创建/调用结果不明，先查真实状态，不能盲目重复。测试应分别覆盖确认、拒绝/取消、重复、创建失败、发现失败及第二次使用。

## 项目与 Work 导航

先列出实际已有项目/Work，核同名与归属。用户确认后按当前工具创建或移动；记录真实 ID、名称、路径和回执。某些环境不能创建项目、不能把远端 Work 加入云项目，或没有新 Work 工具，应说明具体限制。保存一个目录或页面不等于平台项目/Work。能完成的 Skill 与资料库维护继续做，不能把无法创建的对象报成已创建。

每次收尾给清楚的下一次执行入口，例如实际 Work 链接/ID、项目名和 Skill 调用句，并说明还需用户提供哪个输入。避免向新手堆砌实现细节。

## 分层回执

分别记候选待选、已确认、已创建文件、已安装、已发现、首次调用通过、第二次换输入通过，以及取消/失败/未运行/阻塞。回执引用实际文件 hash 或版本、工具返回和输出，不把人工填的状态当平台证据。真实使用和匿名演练分开；测试提示词中的模拟同意不能当用户真实同意创建其私人工作 Skill。

收到后续验证结果后，追加带来源和时间的新回执，并同步工作台、入口与当前项目状态；旧取消和旧未完成状态留作历史，不继续充当当前状态。正式验收在每个阶段结束时保存可读的输入、输出和状态快照及其 hash；只有 hash 而没有对应旧正文，不能独立证明先前阶段写了什么。

未来复用仍以当次用户目标和资源状态为准；不要在通用 Skill 里硬编码某人的经历、私人路径、账号或标准答案。未经授权不向朋友分享 Skill 或私人资料。
