# 独立原文审核与修订闭合

首次建库及内容复验使用本流程。目标是检查生成者事实清单本身是否漏提；不是用页数、哈希或关键词证明语义完整。沿用七类与唯一可写主来源，不增加账户权限，不要求用户先写个人档案。

## 1. 固定获准原文与审核范围

保存本轮实际返回原文、真实消息身份、作者依据、读取边界和用户排除。原文快照与生成者的处置、事实清单分开。审核范围包含本轮获准且已读的记录及必要上下文，包括拟排除、隔离、仅作上下文或脱敏的部分；不能只交成功提炼的retained子集。

尚未读取的部分只报告边界，不由审核者擅自补读其他账户、链接或目录。用户明确排除的内容不得为审核恢复。较长来源可分批，逐批记原始记录ID、已审范围和续接位置；抽样不代表全部已审。

## 2. 分离上下文先读原文

使用本次实际可用、获准的独立执行上下文。审核者第一阶段只接收授权与范围、固定原文、必要原文上下文、通用Skill和隐私规则，不接收生成者清单、候选正文、旧库、旧验收答案或具体失败提示。

审核者逐记录或相关源段保存独立观察：有来源的事实、经历、状态、动机、依赖、选定方案、限制，以及具体排除理由和不确定性。判断是否拆分的依据是含义能否分别纠正、改变建议或限制执行；不规定每条至少几个事实，也不要求每个分句入档。合理合并须仍保留各项含义及相互关系。

观察中每个已审记录有覆盖位置或有据的“不生成新事实”理由。短确认需定位相邻提案和实际指代；无个人信息的过程文本不强迫转成经历。类别提示不是封闭答案表，勾选完类别不能证明穷尽。

在看到候选前保存这份观察、来源哈希和实际调用顺序证据。优先使用真实分离的执行上下文；在同一上下文改称“审核员”或自填independent=true不够。哈希与时间用于版本关联，不证明隐藏记忆不存在。能力不支持分离时保留independence_unverified，不伪造独立审核。

## 3. 保存观察后再开放候选

此时才向审核者提供生成者清单、记录处置理由和实际读回正文。两向比较：

- 原文观察到正文：每个有用含义在哪个主条目承接；未承接时是否有具体、成立的排除或待核理由。原文仍在审计记录中不等于正文已提炼。
- 正文到原文：核作者、对象、时态、确认层级、否定、条件、顺序与适用范围，避免一个“已交付”主题吞掉同条消息的方案、依赖和禁令。

属性脱敏只删除不必要的属性，不自动抹去原文支持的定性经历和为何继续／暂停；也不能从数字猜未说过的动机。明确排除定性内容则遵守，不为覆盖率恢复。隔离或转述归属可与“作为历史任务线索保存、未经本人确认”并存，不自动升级用户事实，也不整条丢弃有用边界。

局部修改须核修改对象、允许范围、明确不改的部分、依赖版本及适用时间；不是要求复制所有实现细节。只保“优化过”不足以承接会影响后续工作的限制，历史要求也不能升级永久偏好或成为本轮执行授权。

观察与生成者清单不同，不默认取并集。每项差异回原文判定；审核者也可能误判，允许有证据地驳回。争议保留disputed，不由生成者删掉问题制造零发现。

## 4. 修订、复核与版本绑定

实质遗漏或含义改变先标needs_revision，保存当前失败快照。发现记录包含：稳定问题ID、原始记录定位、缺失或改变的含义、影响、处置及目标定位。根据原文重新核定正文，不直接粘贴审核者写的标准段落。

在授权目标的可修订版本修改并读回主条目及全部受影响投影。不得改已冻结件；用户要求先冻结首次结果时，先冻结并报告首次结论，后续修订另建版本且保留前版。修订版通过也不能改写成首次干净运行通过。

独立审核者复核新版本：问题是否真正解决、有无新增错误；事实拆分或脱敏／排除理由改变时重看同记录其余含义及必要上下文，不能只找到新短语便关闭。审核误判可记录rejected_with_evidence，由独立复核确认；尚有open或disputed不得宣告限定范围内容通过。

保存审核回执，至少明确：

- 本轮源快照与实际已审记录范围、原文观察版本、独立执行与先后顺序的实际证据及限制。
- 被审核的正文文件／页面身份和版本（可用hash、sequence或实际读回版本）；不能只写日期或“最新版”。
- 每项发现、修订位置、独立复核结论与证据；没有发现也显式记空列表。
- 尚未审范围、未读／排除边界、最终限定结论和未运行阶段。

来源变化使对应原文观察和结论过期；重新审新增／变化范围及必要上下文。正文变化使相关复核过期；不可继承旧版通过。若无法可靠识别影响范围，重审本轮已审范围。字节完全未变且有证据时可沿用对应结论，避免无理由重复检查。

机械工具可以核回执存在、身份和版本关系，但不能认证回执作者独立或语义判断正确。content_review.py的annotations_matched仍只说明所列标注匹配，不能替代本流程，也不能改名为semantic_complete。

## 5. 能力不足与下一次使用

没有独立上下文、范围尚未审完、原文歧义未解、争议未决或迭代没有进展时，交付可查看的有源草稿及未闭合列表，分别标independence_unverified、review_partial、source_unresolved、disputed或semantic_review_incomplete。不得因停止迭代把状态改为通过。已确认的事实仍可使用；受问题影响的建议保持待核。

写入被拒绝时记录remote_write_blocked，不换入口绕过；本地审核通过也不证明远端保存完成。用户确认、工作流创建／安装／示范和新会话换输入验证各自另验，不用审核回执冒充。

下一次干净运行只接收授权、通用安装Skill及本轮获准原文和能力限制，不接收旧正文、私人差异、已知漏项或标准答案。当前运行内有记录的修订不能重新命名为新盲跑。公开回归只用全新虚构材料，至少测试“生成者清单和正文同时漏项”，并有含义完整的合理合并对照，避免靠拒绝所有压缩过关。
